## 0. 한 장 요약

형님 아이디어 셋을 **숫자 하나("영토 단계" 1~5)** 로 묶는다.

| 아이디어 | 이렇게 만든다 |
|---|---|
| ① 마을이 자란다 | 성 안에 **주거 자리** 12곳을 둔다. 영토 단계가 오르면 자리마다 텐트 → 오두막 → 돌집 → 그리스 마을집으로 바뀐다 |
| ② 시민이 병사가 된다 | 시민이 집에서 나와 **막사에 들어갔다가 장정으로 나와** 거치대에서 창·방패를 받아 성문으로 간다. 옷 갈아입는 장면은 건물 안에 숨긴다 |
| ③ 거인을 죽이면 땅이 커진다 | 성벽 단계의 신호를 본부 레벨에서 **"무찌른 적"** 으로 바꾼다. 영토 2 = 도적 소굴, 영토 3·4·5 = 거인 1·2·3 |

한 줄로: **거인을 이긴 순간 성벽이 넓어지고 → 새 땅에 폐허가 드러나고 → 텐트가 집이 되고 → 시민이 늘어 → 다시 300을 채워 다음 거인에게 간다.**

## 1. 컨셉과 어떻게 맞물리나

[`concept-core.md`](concept-core.md)의 감정 구간마다 이 설계가 하는 일:

| 구간 | 컨셉 원문(요지) | 이 설계가 더하는 것 |
|---|---|---|
| **위기** | 행복한 마을, 가족·아이로 보호본능. 거인이 주민을 짓밟으며 온다 | **지킬 사람이 처음으로 화면에 생긴다.** 텐트 사이를 오가는 시민·아이. 거인이 다가오면 시민이 그쪽을 바라보고, 아이는 텐트로 숨는다. 지금 기지에는 병사뿐이라 "무엇을 지키나"가 비어 있다 |
| **희망** | 300 용사를 길러 협곡으로 | 300이 **밖에서 온 사람이 아니라 우리 마을 사람**이 된다. 시민이 막사로 걸어 들어가 용사가 되어 나온다 |
| **시급성** | 실시간으로 다가오는 거인, 그 전에 300 | 거인이 가까워질수록 막사로 가는 시민이 잦아진다(훈련 주문이 걸려 있을 때). 마을이 서두르는 것이 보인다 |
| **성취감** | 300 vs 1, **마을 환호** | 이기면 시민이 광장에 모여 환호(지금은 문구뿐 — [`chapter1-300.md`](chapter1-300.md) "아직 안 한 것"). 이어서 **성벽이 넓어지고 텐트가 집으로** 바뀐다 = 이긴 대가가 땅과 마을로 남는다 |
| **절망** | 거인 10마리가 동시에 | 마을이 커진 뒤라 **잃을 것이 크다**. 텐트촌일 때보다 집 마을일 때 절망이 무겁다. (거인 10은 다음 장 — 이 문서 범위 밖) |
| **복수** | 근거지 파괴, 목마 건조 | 목마 건조장(본부 Lv.6)이 자랄 땅도 결국 거인을 몰아내고 얻는다 |

### 컨셉의 "영지 개간은 소모됨"과 부딪히지 않나

컨셉은 "영토 개간/확장 시뮬레이션이 아니라 건축물 건설 시뮬레이션"이라고 했다. 이 설계의 땅 넓히기는 **개간 작업(땅을 사고, 치우고, 기다리기)이 아니다.**
땅은 **싸움의 결과로만** 넓어진다 — 따로 누를 버튼도, 비용도, 타이머도 없다. 플레이어가 하는 일은 여전히 "병사를 길러 거인을 무찌르기"이고,
넓어진 땅은 그 보상을 눈으로 보여 주는 장치다. 탑포스도 기지 레벨마다 성벽이 넓어지지만 그건 "개간"으로 느껴지지 않는다
([`topforce-early-game.md`](topforce-early-game.md) — 성벽이 넓어지고 빈 칸에 망치 아이콘).

## 3. 단계표

**영토 단계 하나가 성벽·마을·시민을 함께 정한다.** 본부 레벨은 영토 단계를 넘을 수 없다(4절 규칙).

| 영토 | 열리는 신호 | 이때 본부 | 성벽(아트 키트) | 성 안 넓이* | 텐트 | 집 | 주거 자리 | 보이는 시민 (그중 아이) |
|---|---|---|---|---|---|---|---|---|
| **1** | 처음부터 | Lv.1 | L1 급조 목책 | 768㎡ | **6** | 0 | 6 | 8 (2) |
| **2** | **도적 소굴** 함락 (`front.outpost` ≥ 1) | Lv.2 | L2 보강 목책 | 1115㎡ | **10** | 0 | 10 | 12 (3) |
| **3** | **거인 1** 처치 — 300 vs 1 (`threat.giant_1.won`) | Lv.3 | L3 막돌 + 말뚝 | 1330㎡ | 6 | 오두막 **4** | 10 | 16 (4) |
| **4** | **거인 2** 처치 (`threat.giant_2.won`) | Lv.4 | L4 사암 + 성가퀴 | 1887㎡ | 2 | 돌집 4 · 오두막 6 | 12 | 20 (5) |
| **5** | **거인 3** 처치 (`threat.giant_3.won`) | Lv.5 | L5 깃발 성벽 | 2021㎡ | 0 | 마을집 4 · 돌집 8 | 12 | 24 (6) |

\* 넓이는 지금 값(주거 자리 빼고). 주거 자리를 성벽이 감싸게 하면(5절 추천) 단계마다 대략 150~300㎡씩 더 넓어진다 — 로직 세션이 RealData 시험으로 다시 잰다.

- **주거 자리는 바뀌기만 하고 옮기지 않는다.** 마을 가운데(본부)에 가까운 자리부터 먼저 집이 된다 — "먼저 온 사람부터 집을 짓는다".
  그래서 영토 3이 되면 안쪽 텐트 4개가 그 자리에서 오두막이 되고, 바깥쪽 텐트는 그대로 남는다.
- **보이는 시민은 그림의 수**다. 300(용사)이나 번영도 같은 계산 숫자와 묶지 않는다(형님 결정 4 — 1차는 그림만).
  시민 한 명이 막사로 가면 잠시 뒤 집에서 다른 시민이 나와 수를 맞춘다. "마을 사람이 끝없이 병사가 되어 나간다"가 보이면 된다.
- 첫 확장(영토 1→2)을 거인이 아니라 **도적 소굴**로 둔 이유: 첫 거인은 본부 Lv.2에 나타나 25분을 걸어오는 큰 사건이다.
  그 전에 작은 거인을 끼우면 "300 vs 1"의 무게가 줄어든다. 대신 "도적을 몰아낸 가까운 땅 → 거인이 차지한 먼 땅" 순서가 이야기로도 맞다.
  (형님 결정 2)

## 4. 거인 처치를 영토 신호로 — 무엇을 바꾸나

### 4-1. 두 가지 방법

| | A. 본부 조건에만 거인을 넣는다 | **B. 성벽 단계가 자기 조건을 갖는다 (추천)** |
|---|---|---|
| 땅이 넓어지는 순간 | 거인을 이기고 → 본부 공사가 끝날 때 | **거인을 이긴 바로 그 순간** (환호 → 성벽이 솟는다) |
| 그 사이 화면 | — | 넓어진 땅에 아직 못 짓는 폐허가 보인다 → "본부를 올리면 저기를 되찾는다" (탑포스의 "성벽이 넓어지고 빈 칸에 망치") |
| 바꿀 것 | 데이터만 (`progression.json`·`chapter1.json`·`quests.json`) | 데이터 + Core 작은 변경(성벽 단계가 조건을 읽음) + 화면 한 줄 |
| 형님 아이디어와 | "본부를 올리면 넓어진다"로 읽힌다 — 한 박자 늦다 | "거인을 죽였더니 땅이 커졌다" 그대로 |

### 4-2. B의 규칙 (지켜야 할 것 하나)

> **본부 Lv.N의 조건에는 영토 N의 조건이 반드시 들어 있다.**

그러면 본부가 땅보다 앞서는 일이 없다 → **열린 건물은 늘 성 안에 있다** → "지을 수 있는데 성 밖이라 못 짓는다" 같은 막힘이 생기지 않는다.
RealData 시험이 이 규칙을 확인하게 한다(어기면 게임 시작 때 멈추고 이유를 댄다 — `CLAUDE.md` §2-5 "거부에는 이유").

### 4-3. 데이터 초안

**`walls.json` — 단계마다 열리는 조건(`unlock`)을 더한다.** 모양은 본부 조건과 같은 꼴(`kind`·`target`·`amount`)이라 같은 검사기를 쓴다.
`hqLevel`은 뜻이 "열리는 본부 레벨"에서 **"이 성벽이 둘러쌀 건물 = 본부 Lv.N까지 열리는 건물"** 로 바뀐다(값은 그대로).

```json
"tiers": [
  { "hqLevel": 1, "gateLength": 4, "unlock": [] },
  { "hqLevel": 2, "gateLength": 4, "unlock": [ { "kind": "Counter", "target": "front.outpost",      "amount": 1 } ] },
  { "hqLevel": 3, "gateLength": 8, "unlock": [ { "kind": "Counter", "target": "threat.giant_1.won", "amount": 1 } ] },
  { "hqLevel": 4, "gateLength": 6, "unlock": [ { "kind": "Counter", "target": "threat.giant_2.won", "amount": 1 } ] },
  { "hqLevel": 5, "gateLength": 6, "unlock": [ { "kind": "Counter", "target": "threat.giant_3.won", "amount": 1 } ] }
]
```

| | 거인 1 (지금) | 거인 2 "거인 형제" (새) | 거인 3 "돌 던지는 무리" (새) |

| 영토 | → 3 | → 4 | → 5 |

- **목표는 계속 300이다.** 영화 300도 300으로 끝까지 싸운다. 대신 적이 세지므로 **같은 300이 더 강해져야** 이긴다 —
  훈련소·치유의 집·제철소 레벨이 주는 강화(`battle.json` buffs)가 그 역할이다. 탑포스의 "다음 기지는 더 세서 안 키우면 밀린다"와 같은 문법.
  (형님 결정 3 — 500·1000으로 늘리는 안도 있다)
- 이긴 뒤 살아남은 용사(거인 1 기준 약 87명)만 남으므로 **다음 거인 전에 다시 300을 채운다** = 시민이 다시 막사로 간다. 고리가 닫힌다.
- 배수와 마릿수는 **감으로 쓴 값**이다. 맞추는 기준: 그 본부 레벨의 강화를 받은 300명이 **생존 30~90명으로 이기고, 200명이면 진다.**
  `거인_하나는_300이면_이기고_절반이면_진다` 시험과 같은 꼴로 거인 2·3 시험을 붙여 맞춘다.
- 이야기 문구 키: `story.giant_2.start/win/lose`, `story.giant_3.start/win/lose`, 땅이 넓어질 때 `story.territory.2`~`.5`
  (예: "거인이 짓밟던 언덕을 되찾았다. 피난민들이 텐트를 걷고 집을 올리기 시작한다").

## 5. 마을 그리기 — 주거 자리와 시민

### 5-1. 주거 자리 (집이 설 곳)

| | ① 배치 파일에 자리를 정해 둔다 **(추천)** | ② 빈틈에 자동으로 채운다 |
|---|---|---|
| 방법 | `base-layout.json`에 주거 자리 12곳(각 6m × 6m)과 "몇 단계에 생기나"를 적는다 | 성벽 안, 건물·길이 없는 칸을 계산해서 채운다 |
| 성벽 | **성벽이 집까지 감싼다** — 형님이 원한 "외곽이 마을 형태를 따라서"와 맞다 | 성벽은 건물만 감싸고 집은 남는 틈에 — 틈이 좁으면 집이 안 들어간다 |
| 고치기 | 나중에 만들 기지 저작 툴(씬에서 옮기고 같은 JSON에 저장)로 손으로 맞춘다 — "씬에서 한 것이 곧 게임" | 손으로 못 맞춘다 |

①로 하면 `WallRing.VillagePatches`가 그 단계까지 생긴 주거 자리도 마을에 넣는다. 처음 자리는 `tools/seed-layout/`이 본부 둘레에 씨를 뿌린다.
주거 자리는 **누를 수 없는 자리**다 — 복구·업그레이드 대상이 아니고, 영토 단계가 오르면 저절로 바뀐다.

단계별 모습은 새 데이터 파일 `Assets/Data/village.json`에 둔다(초안):

```json
{
  "_comment": "영토 단계별 마을. 주거 자리는 본부에 가까운 순서로 바뀐다. 설계 docs/village-growth.md",
  "stages": [
    { "stage": 1, "slots": 6,  "looks": [ { "look": "tent", "count": 6 } ],                                    "citizens": 8,  "children": 2 },
    { "stage": 2, "slots": 10, "looks": [ { "look": "tent", "count": 10 } ],                                   "citizens": 12, "children": 3 },
    { "stage": 3, "slots": 10, "looks": [ { "look": "hut", "count": 4 },  { "look": "tent", "count": 6 } ],    "citizens": 16, "children": 4 },
    { "stage": 4, "slots": 12, "looks": [ { "look": "stone", "count": 4 }, { "look": "hut", "count": 6 }, { "look": "tent", "count": 2 } ], "citizens": 20, "children": 5 },
    { "stage": 5, "slots": 12, "looks": [ { "look": "villa", "count": 4 }, { "look": "stone", "count": 8 } ], "citizens": 24, "children": 6 }
  ]
}
```

판단(어느 자리가 어떤 모습인가)은 Core에 둬서 시험을 붙인다: 수가 표와 맞는가, 자리가 건물과 겹치지 않는가(`BaseLayout.Validate`),
모든 자리가 성벽 안쪽 여유 안에 드는가.

**바뀌는 연출**: 성벽이 다 솟은 뒤(약 3초) 이어서 — 바뀌는 텐트가 접히며 가라앉고, 먼지 속에서 집이 솟는다(성벽과 같은 솟기 연출). 새로 생긴 자리에는 텐트가 펼쳐진다.

### 5-2. 시민

| 하는 일 | 언제 |
|---|---|
| 집 문 ↔ 광장(본부 앞) ↔ 일터(목공소·채석장·농장) 사이를 걷는다. 일터에서는 나무·돌 짐을 들고 온다 | 늘 |
| 아이는 본부 앞·텐트 사이에서 뛰어논다 | 늘 |
| 거인 쪽을 바라보며 멈춘다. 아이는 집으로 뛰어간다 | 거인이 다가오는 동안(`ThreatPhase.Approaching`) |
| 모두 집 안으로 (거리가 빈다) | 거인 도착·협곡 전투 중 |
| 광장에 모여 **환호** | 거인을 이긴 직후 — 그다음 성벽이 넓어진다 |

### 5-3. 시민 → 병사 (지금 징집 흐름을 바꾸는 곳)

```
지금:  뒷문(맨손 장정) → 병영 앞 → 훈련소 거치대(창·방패) → 성문 → 전선
바꾼 뒤: 집 문(시민) → 막사 안으로 들어감(1~2초 사라짐) → 장정으로 나옴(맨손) → 훈련소 거치대 → 성문 → 전선
```

- **옷 바꾸는 장면은 건물 안에 숨긴다.** 시민 모델이 막사 문에서 사라지고, 잠시 뒤 지금의 맨손 장정 모델이 나온다. 바꾸는 동작 아트가 필요 없다.
- 거치대 이후는 지금 그대로(`FrontlineDirector` 무기 배급 절). 출발점만 뒷문 → 무작위 집 문으로 바뀐다.
- 병영에 훈련 주문이 걸려 있으면 막사로 가는 시민이 잦아진다(시급성). 다 자란 용사는 지금처럼 병영 앞에 줄 선다.
- **뒷문은 "피난민 문"으로 남긴다**(형님 결정 6): 영토 1~2 동안 가끔 짐을 진 피난민이 뒷문으로 들어와 텐트로 간다 — 텐트촌이 사람이 모여드는 곳임을 보여 준다.

### 5-4. 이 설계로 같이 풀리는 것

[`concept-gap.md`](concept-gap.md)·[`chapter1-300.md`](chapter1-300.md)에 "아직 안 한 것"으로 남은 것 중 시민이 있어야 되는 것들:
오프닝(행복한 마을·주민·아이 → 카메라가 빠지며 거인), 거인이 주민을 짓밟으며 오는 연출, 마을 환호. 이 문서 범위는 아니지만 시민 모델·동작이 생기면 바로 붙일 수 있다.
